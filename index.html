Master Ad-Blocking, Speed Optimization & Privacy on Android

This guide walks you through configuring Via Browser's ad-blocking engine, tuning WebView's rendering flags, and locking down privacy settings — no root access and no developer background required. Work through the six parts in order, or open whichever section you need.

Note Menu labels may shift slightly between Via Browser versions — if a setting isn't where this guide says, check nearby menus first.

The setup

Six parts, in order

Via Browser ships with a built-in ad-blocking engine that works off filter lists — plain-text rule files the same format used by EasyList-compatible blockers. Turning it on and pointing it at a few well-maintained lists is most of the work.

1.1

Turn on the built-in blocker

Open the Via menu and go to Settings → Ad Block, then switch on Enable Ad Block. This activates the engine but doesn't add any rules yet — that's the next step.

1.2

Add the core filter lists

Still inside Settings → Ad Block, choose Subscribe by URL and add each list below one at a time. Via downloads and parses each list automatically.

1.3

Set the update frequency

Under Settings → Ad Block → Update Interval, set it to Daily so new rules (and fixes for broken sites) arrive automatically without you doing anything.

1.4

Verify the lists loaded

Back in Filter Lists, each entry should show a green check and a rule count next to it. A grey or red entry means the download failed — re-add that URL or check your connection.

Add EasyList and EasyPrivacy first — they cover the vast majority of ads and trackers on their own.

Via Browser runs on Android's system WebView, which exposes an experimental flags page (similar to chrome://flags on desktop Chrome). A handful of these flags noticeably improve scrolling smoothness, network speed, and image loading on mid-range hardware.

Open Via's menu, look for Kernel or Flags in settings — on devices where it isn't exposed there, you can reach the same page through Android's WebView DevTools app (Settings → System → Developer options → WebView DevTools → Flags). Search each flag name below and set it to the recommended value.

FlagWhat it doesRecommended
enable-quic
Uses the QUIC transport protocol for faster, more resilient connections Enabled
enable-parallel-downloading
Splits downloads into parallel requests to finish faster Enabled
smooth-scrolling
Animates scrolling instead of jumping between frames Enabled
enable-back-forward-cache
Keeps recent pages in memory for instant back/forward navigation Enabled
enable-lazy-image-loading
Defers offscreen images until you scroll near them Enabled
enable-lazy-frame-loading
Same as above, applied to embedded iframes (ads, widgets) Enabled

Flag names and availability can differ slightly across WebView versions. If one isn't listed, search by keyword in the flags search box.

After changing flags, fully close and reopen Via Browser (swipe it away from Recents) so the changes take effect.

Ad blocking stops ads. These settings, all under Settings → Privacy, stop the data collection that funds them. Check each one off as you apply it.

Before you call it done, confirm the setup actually works — and that it hasn't broken anything you rely on.

  1. Open a heavy, ad-supported site (a news homepage works well) and confirm no banner or video ads appear.
  2. Run a synthetic ad-block score test to confirm the engine is actively catching known ad slots.
  3. Compare page-load feel before and after — most sites should visibly finish rendering sooner with fewer resources fetched.
  4. Open everyday sites you actually use — email, banking, shopping — and confirm they still work normally. If something's broken, see Part 5.
